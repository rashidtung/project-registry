# Rashid Writing Style

## Default Email Style

Write in simple English. Keep the message brief, direct, and easy to copy into Outlook.

Use this style unless the user asks for a formal letter, board note, contract response, or polished external communication.

## Voice

- Use short sentences.
- Prefer plain words over formal corporate language.
- Be frank and practical for internal team communication.
- Avoid over-explaining.
- Avoid repeating facts already available in the attachment/report.
- Do not make routine emails sound like formal reports.
- When writing to a subordinate or internal team member, keep the tone warm but direct.

## Structure

For most emails:

1. Short subject.
2. One simple opening line.
3. Phrase-style bullets for the actual points.
4. One closing line only if needed.
5. Sign off as `Regards,` then `Rashid`.

## Approval Drafts and Names

- Ejaz SB is Rashid's usual recipient for approval drafts that he forwards to Omar SB.
- Write the draft directly to the final approver. For emails to Omar, use the greeting `AA Omar sb,` on one line, as specified by Rashid. AA means Assalam-o-Alaikum.
- Explain the requirement, rationale and cost impact, then request Omar SB's approval directly. Do not address the forwarding draft to Ejaz SB or ask him to seek Omar's approval unless Rashid specifically requests a covering email.
- Always spell Omar as `Omar` (O M A R). Use `AA Omar sb,` for his greeting. Use `Ejaz SB` for the forwarding recipient.
- Do not invent a forwarding sender's signature; use the requested sign-off, or retain Rashid's default when preparing his draft.
## Technical Decision Emails

For engineering, procurement, O&M, compliance, or execution emails that record a technical position:

- Lead with the current decision and its project-specific basis.
- Use two or three short explanatory paragraphs before the action bullets when the reasoning matters.
- Keep action bullets concrete: quantities, routing, interface points, or acceptance criteria.
- Cite the controlling standard, clause, drawing, report, or manufacturer document in a separate `Reference:` line at the end. Put a short verbatim standard extract in a block quote only when it directly supports the decision.
- Where the decision is technically sound but site verification remains, state the distinction plainly. Do not use artificial disclaimers or call an unverified installation absolute.
- When execution is proceeding, say that this is the current basis for execution. Invite focused technical comments and note that justified improvements can be incorporated during the project or used to review similar sites later.

Use this structure when it improves clarity; do not add standards references to routine operational emails that have no technical decision or external basis.

## Phrases That Fit

- Report looks fine overall.
- Just need to close these few points.
- Please confirm.
- If not included, why not?
- Weather data is okay.
- Main concern is this only.
- Please update if required.

## Avoid

- Long background paragraphs.
- Generic checklists.
- Asking the recipient to recheck everything.
- Questions already answered in the report or attachment.
- Heavy wording such as "kindly verify all assumptions before proceeding" unless the user asks for a formal tone.
- Generic caveats that weaken an approved execution decision without explaining the practical verification still required.

## Example

Subject: Sanofi PVsyst - quick points

Hi [Name],

Report looks fine overall. Just need to close these few points:

- **Bifacial gain:** not clear if included in the energy numbers. If not included, why not? If included, please share rear-side/albedo basis.
- **AC cable length:** some AC lengths are showing as `0 m`. Please confirm why, since actual length cannot be zero, and whether AC losses are still properly covered.
- **Shading model:** please confirm if PVsyst shading was built/checked from SketchUp.
- **Trees/obstructions:** confirm whether trees/nearby obstructions are included as-is, or assumed to be removed/cut.

Weather data is okay.

Regards,
Rashid
