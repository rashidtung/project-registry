# SPL Office Work Two-Level Structure

## Apply the non-negotiable rule

Treat `D:\iCloudDrive\SP Laptop\SPL Office Work` as the office-work root.

- Keep the established category folders directly under the root.
- Allow one additional folder layer inside each category to divide the work by project, site, client, activity, or another useful unit.
- Allow multiple work-division folders within a category when needed.
- Never create a folder inside a work-division folder.
- Keep files directly inside either the category folder or its work-division folders.
- Treat every directory deeper than `SPL Office Work\Category\Work Division` as a violation.

## Handle conflicts

If an operation, application, template, archive, or file format requires deeper nesting:

1. Stop before creating a third folder level beneath the office-work root.
2. Offer a flat-file alternative within the relevant work-division folder.
3. Otherwise propose a location outside `SPL Office Work` and obtain Rashid's approval before using it.
4. Never silently make a deeper exception inside the office-work root.

## Rework content safely

- Audit first and report folders that exceed the allowed depth before changing them.
- Preserve the established root-level categories.
- Use the single allowed inner layer to divide work deliberately instead of creating deeper hierarchies.
- Resolve duplicate filenames and ambiguous destinations explicitly.
- Do not move, rename, overwrite, merge, or delete existing content without authorization for that reorganization.

## Validate every change

After any authorized file operation, verify that:

- every category folder is a direct child of the root;
- every work-division folder is a direct child of a category folder; and
- no work-division folder contains another directory.

If validation finds a directory three or more levels beneath the root, report it and do not describe the organization as compliant.
